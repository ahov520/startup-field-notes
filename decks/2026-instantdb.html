CASE CUT

InstantDB 复盘

美国 · 实时同步「现代 Firebase」→ OpenAI 人才收编
核心命题：1.7万用户/40万应用 ≠ 可独立长大的托管云

01 · 一句话要害

团队加入 OpenAI；新签关闭；云应用最迟 2027-08-31 关停——人才收购 + 产品日落，不是原主体云业务永续。

02 · 它做成了什么

  • 现代 Firebase 产品句清晰，打动顶级技术天使
  • 开源 Show HN 级热度与 $3.4M 种子轮
  • 踩中 Agent 写应用的后端缺口
  • 长迁移窗 + 开源自托管，对用户体面
  • 走完想法→YC→开源→种子→收编全弧

伤口① 使用量亮、经济不透明

事务量可融资，垫不高独立云投票

伤口② 入口被 Agent 改写

分发权上移，独立品牌变零件候选

伤口③ 明星资本压缩慢生意

光环提高「被人定价」概率

伤口④ 开源=收编软着陆垫

关云变得可辩护，租金可放弃

伤口⑤ 自托管退回运维

客户依赖的是你的值夜班

对照

案例要点
Character.AI / Inflection人进大厂，产品名义或淡出
garnix → Shopify开源+关云，利基基建同族
Instant → OpenAIAgent 基建叙事吃掉独立云

刀口建议

  • 报事务前先报付费续约应用数
  • 分清卖云还是卖 Agent 模块
  • 开源策略含用户退出预案
  • 明星天使下一句：不融资也能活

结论

Show HN 与顶级天使 ≠ 可独立长大的开发者云；默认结局往往是人进大厂、代码开源、云按日程熄灯。
